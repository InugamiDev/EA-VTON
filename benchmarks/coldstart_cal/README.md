# Benchmark B3 — Cold-Start Preference Calibration

After a user picks `k_liked` items from a stratified seed grid (no interaction history available), produce a calibrated re-ranking of a candidate pool that reflects the user's visual preferences.

## Task

**Input per user**:
- 18 stratified seed items (deterministic — generated by the SQL window function in the catalog)
- `liked_idx`: indices of `k_liked ∈ [3, 8]` items the user picked from the seed grid
- A 500-item candidate pool (deterministic — same for all users)

**Output**: an ordered list of pool item ids.

## Strategies under test

1. **random_seed** — uniform random 18-item seeds
2. **stratified_sql** (this paper) — SQL window function picking 1 item per `(neckline × silhouette × color_temperature)` cell
3. **dpp_proxy** (Nguyen UAI 2024 baseline) — greedy farthest-point in CLIP space

For each strategy, the calibrated score is

```
s'(item) = (1 - δ) · s_FFM(item) + δ · cos(emb(item), centroid(liked))
```

with δ swept over `{0, 0.1, 0.3, 0.5, 0.7, 1.0}`.

## Synthetic users (noise_p = 0.4)

Real users are noisier than "all 4 picks match exact attribute combo." We construct synthetic users by:
1. Picking preferred `(neckline, silhouette, color_temp)` triple
2. For each of 4 liked items, independently flipping each attribute to a random value with probability `noise_p = 0.4`

This makes the FFM silver-label task non-trivial (~57% R@10 baseline) so the calibration can demonstrate effect.

## Metrics

| Metric | Description | Used for |
|---|---|---|
| **align@K** | Mean cosine similarity of top-K to user CLIP centroid | Primary: does calibration produce visually similar recommendations? |
| **Recall@K** | Leave-one-out recall of held-out 4th liked item in top-K | Secondary: does calibration find specific items the user would like? |
| **Kendall's τ** | Rank correlation between calibrated and base FFM ranking | Confirms calibration produces meaningful reshuffling |

## Baselines reported in v2 paper

200 synthetic users, n_liked=4 (3 train + 1 held-out), pool=500, seed=42.

### Visual alignment (top-K cosine to user centroid — higher is better)

| Strategy        | align@10 δ=0 | δ=0.3 | δ=0.7 | δ=1.0 | Δ(δ=1.0 − δ=0) |
|-----------------|-------------:|------:|------:|------:|---------------:|
| random_seed     | 0.577        | 0.622 | 0.680 | 0.732 | **+0.155**     |
| stratified_sql (this paper)  | 0.587 | 0.632 | 0.685 | 0.735 | **+0.147** |
| dpp_proxy (Nguyen UAI 2024)  | 0.590 | 0.634 | 0.684 | 0.732 | **+0.142** |

### Leave-one-out Recall@10 (held-out 4th item appears in top-10 — higher is better)

| Strategy        | δ=0   | δ=0.3 | δ=0.7 | δ=1.0 |
|-----------------|------:|------:|------:|------:|
| random_seed     | 0.585 | 0.535 | 0.400 | 0.110 |
| stratified_sql  | 0.560 | 0.525 | 0.395 | 0.080 |
| dpp_proxy       | 0.570 | 0.550 | 0.395 | 0.105 |

### Kendall's τ (calibrated vs base — lower magnitude = more reshuffle)

| Strategy        | τ@δ=0.1 | τ@δ=0.3 | τ@δ=0.5 | τ@δ=0.7 | τ@δ=1.0 |
|-----------------|--------:|--------:|--------:|--------:|--------:|
| random_seed     | 0.054   | 0.042   | 0.027   | 0.015   | -0.003  |
| stratified_sql  | 0.057   | 0.043   | 0.029   | 0.012   | -0.014  |
| dpp_proxy       | 0.057   | 0.047   | 0.024   | 0.025   | 0.010   |

## Honest reading

**Strategy invariance.** Across all three metrics, the three seed strategies are within noise of each other. **Stratified SQL ≈ DPP proxy ≈ random** for the calibration's downstream effect. This supports the paper's "operational simplicity at no measurable cost" claim — a single SQL `WHERE … ORDER BY … LIMIT` query matches the more complex DPP baseline from Nguyen UAI 2024.

**δ tradeoff.** The visual-alignment metric monotonically increases with δ (more calibration = more visually similar), while leave-one-out recall decreases. δ=0.3 is a balanced default: substantial alignment gain (+0.05 cosine) at a modest recall cost (−0.04 R@10).

**Limitation.** This is a silver-label benchmark with synthetic users. A real user study (N=30+, deferred to v2 paper revision) is needed for accept-level claims about deployment value. Reported here only as the benchmark protocol numbers.
